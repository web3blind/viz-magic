## ЧАСТЬ 1 — МИР

### 1.1 Космология

Мир называется **The Weave** (Ткань). Реальность соткана из магической энергии Viz. Основа — **Aetheric Ledger** (Эфирный Леджер) — нерушимая цепь кристаллизованных моментов времени (Блоков). Каждое действие записано навечно.

Ткань постоянно излучает магическую энергию (эмиссию). Она бесформенна, пока существо с Magic Core (SHARES) не канализирует и не направит её.

### 1.2 Фундаментальные Законы

1. **Суверенитет Души.** Никакая сила не может извлечь Core у мага против его воли. (SHARES нельзя отнять.)
2. **Перманентность.** Каждое действие записано навечно. (Иммутабельность блокчейна.)
3. **Сохранение Маны.** Каннелирование Ткани расходует Ману; она восстанавливается только с отдыхом.
4. **Направленный Поток.** Заклинание не тратит богатство кастера — оно формирует эмиссию Ткани и направляет к цели.
5. **Нестабильная Добыча.** Ресурсы из диких зон нестабильны до кристаллизации в убежище.

### 1.3 Пять Школ Магии

| Школа | Стихия | Философия | Цвет |
|---|---|---|---|
| Ignis | Огонь | Разрушение, трансформация | Алый |
| Aqua | Вода | Исцеление, адаптация | Лазурный |
| Terra | Земля | Стойкость, защита, рост | Изумрудный |
| Ventus | Воздух/Шторм | Скорость, уклонение | Серебряный |
| Umbra | Тень | Скрытность, обман, энтропия | Фиолетовый |

**Колесо Доминирования:**
Ignis → Ventus → Terra → Aqua → Umbra → Ignis

Доминирующая стихия: 1.5x урон. Подчинённая: 0.7x.

## ЧАСТЬ 2 — СИСТЕМА ПЕРСОНАЖЕЙ

### 2.1 Идентичность

Один VIZ аккаунт = один маг. Вся история аккаунта = летопись персонажа.

### 2.2 Пять Классов

| Класс | Блокчейн-сродство | Основная школа | Роль | Пассивка |
|---|---|---|---|---|
| Emberblade | Мастерство Award | Ignis | Burst DPS / Дуэлянт | Overcharge: +12% урона за каждые 500 MP сверх базы |
| Aegis Warden | SHARES + делегирование | Terra | Танк / Защитник | Soul Fortress: -20% входящего урона + бонус от делегирования |
| Veilweaver | Зашифрованные объекты | Umbra | Стелс / Контр-игра | Hidden Hand: +15% крит; стратегии с доп. защитой от брутфорса |
| Runescribe | custom_sequence | Terra | Крафтер / Саммонер | Inscription Mastery: +25% качество крафта |
| Pactbinder | Escrow + beneficiaries | Aqua | Поддержка / Брокер | Covenant Resonance: Award союзникам +25% эффективнее |

### 2.3 Статы

| Стат | Управляет |
|---|---|
| Potency (POT) | Сила атакующих заклинаний |
| Resilience (RES) | Снижение урона, пул HP |
| Swiftness (SWF) | Инициатива, уклонение |
| Intellect (INT) | Качество крафта, эффективность |
| Fortune (FOR) | Шанс крита, качество лута |

**Бонус от SHARES:**
```
core_bonus = floor(effective_shares ^ 0.3)
```

| Effective SHARES | Core Bonus | Ранг |
|---|---|---|
| 100 | 3 | Apprentice |
| 1,000 | 7 | Journeyman |
| 10,000 | 15 | Adept |
| 100,000 | 31 | Master |
| 1,000,000 | 63 | Archmage |

Степень 0.3 = сильная компрессия: 10,000x SHARES → только ~10x бонуса. Уровень, экипировка и стратегия компенсируют разрыв.

## ЧАСТЬ 3 — МАГИЧЕСКАЯ СИСТЕМА

### 3.1 Экономика Маны

| Свойство | VIZ | Игра |
|---|---|---|
| Пул | 10,000 basis points | 10,000 Mana Points |
| Регенерация | 432,000 сек (5 дней) 0→100%. Формула: energy += 10000 * elapsed_sec / 432000 | 5 солнечных циклов |
| Трата | Award с X bp | Заклинание стоит X MP |

Все действия конкурируют за один пул маны: бой, лечение, крафт, зарядка локаций.

### 3.2 Маршрутизация Заклинаний (Award Routing)

| Тип заклинания | Award Target | Эффект |
|---|---|---|
| Лечение/Бафф | Аккаунт союзника | Хил/бафф, союзник получает эмиссию |
| PvE Атака | Аккаунт NPC-существа | Урон существу, NPC получает эмиссию (фонд наград) |
| PvP Атака | Аккаунт-синк арены | Урон противнику, эмиссия в призовой фонд |
| Honor Strike | Аккаунт противника | Урон + противник получает токены |
| Крафт | Себе | Самонаправленная эмиссия |
| Территориальный заряд | Аккаунт территории | Вклад в осаду/оборону |

### 3.3 Заклинания (примеры)

**Emberblade:**
- Firebolt (1000 MP, Lv1) — POT × 1.2 урон
- Pyroclasm (3000 MP, Lv10) — POT × 2.5 урон
- Inferno (5000 MP, Lv25) — POT × 4.0 урон (ультимейт)

**Aegis Warden:**
- Stone Fist (1000 MP, Lv1) — POT × 1.0 + 10% RES
- Healing Tide (1500 MP, Lv1) — Хил INT × 2.0 (award союзнику)
- Aegis of Stone (5000 MP, Lv25) — +80% RES, отражение 25%

**Veilweaver:**
- Shadow Bolt (900 MP, Lv1) — POT × 1.0 + 20% крит
- Counterspell (1500 MP, Lv8) — Отмена заклинания противника
- Veil Step (4000 MP, Lv25) — Полное уклонение + гарантированный крит

**Pactbinder:**
- Covenant Heal (1200 MP, Lv1) — Хил INT × 2.5 (усилен пассивкой)
- Bounty Mark (1000 MP, Lv8) — +15% урона всех союзников по цели
- Grand Covenant (5000 MP, Lv25) — Полный хил + щит всей группе

## ЧАСТЬ 4 — БОЕВАЯ СИСТЕМА

### 4.1 За Что Сражаются

| Ставка | Можно отнять? |
|---|---|
| HP / урон | Да — бой наносит |
| Volatile лут (не забанкованный) | Да — победитель забирает |
| Эскроу-ставки (добровольно) | Да — победитель получает |
| Контроль территории | Да — коллективное усилие |
| Ранг / Честь | Да — win/loss влияют |
| Кристаллизованный инвентарь | Нет — только через добровольную ставку |
| SHARES / Core | Никогда — Первый Закон |

### 4.2 Четыре Намерения

| Намерение | Эффект |
|---|---|
| Strike | Атака |
| Guard | Защита |
| Weave | Контр / ловушка / трюк |
| Mend | Лечение / поддержка |

Камень-ножницы-бумага: Strike > Mend > Weave > Guard > Strike

### 4.3 PvE — Охота на Монстров

Один тразакция, мгновенное разрешение:
1. Игрок постит Hunt Inscription + Award NPC-существу
2. Поведение существа — чистая функция от (type, level, stats, block_hash)
3. block_hash неизвестен заранее → честная случайность
4. Клиент вычисляет исход детерминированно

```json
{
  "p": "VM", "v": 1, "t": "hunt", "b": 12340000,
  "d": {
    "creature": "fire_drake",
    "zone": "ember_wastes_north",
    "spell": "firebolt"
  }
}
```

### 4.4 PvP — Ритуальная Дуэль (Commit-Reveal)

```
ФАЗА 1 — ВЫЗОВ (Блок N):
  Игрок A: Inscription + Sealed Sigil (зашифрованная стратегия) + Award

ФАЗА 2 — ПРИНЯТИЕ (Блок M ≤ N + 28800):
  Игрок B: Accept + Sealed Sigil + Award

ФАЗА 3 — РАСКРЫТИЕ (M+100 до M+14400):
  Оба раскрывают ключи шифрования
  Не раскрыл в окне → автоматическое поражение

ФАЗА 4 — РАЗРЕШЕНИЕ (Детерминированное):
  Все клиенты вычисляют идентичный результат:
  - Обе раскрытые стратегии
  - Статы обоих игроков (из цепочки)
  - Block hash = Fate Entropy
```

### 4.5 Формула Боя

Целочисленная арифметика (без float), идентичный результат на любом клиенте:

```
attack = base_power × spell_mult × (energy/10000) × element_mod × equip_mod × fate × class_mod
damage = max(0, attack - defense)
```

### 4.6 Volatile Loot — Решение Проблемы PvP

Предметы из опасных зон — **volatile** (нестабильные) до "банкинга" в безопасном месте:
- Нестабильный лут можно забрать у побеждённого
- Для кристаллизации нужно добраться до убежища
- Создаёт механику эскорта, засад, караванов

### 4.7 Последствия Поражения

| Результат | HP > 0 | HP ≤ 0 ("Fallen") |
|---|---|---|
| Статус | Активен | "Fallen" 12 часов |
| Volatile лут | Забирается победителем | Забирается победителем |
| XP | -5% | -15% |
| Кристаллизованные предметы | Безопасны | Безопасны |
| SHARES | Безопасны | Безопасны |

## ЧАСТЬ 5 — ЭКОНОМИКА, КРАФТ, ТОРГОВЛЯ

### 5.1 Ресурсы

| Валюта | Блокчейн | Роль |
|---|---|---|
| Viz Essence | Liquid VIZ | Торговая валюта, ставки |
| Core Power | SHARES | Не тратится; определяет силу |
| Mana | Energy (bp) | Тратится на все действия |

**Крафтовые материалы:**
- Sparkdust — от боёв → оружие
- Chronicle Ink — от авторских постов → свитки
- Veilstone — от загадок → стелс-снаряжение
- Sealwax — от эскроу-сделок → контрактные предметы
- Echo Shards — от дуэлей → защитная экипировка
- Aether Ore — от территорий → основные материалы

### 5.2 Предметы

Состояния: Volatile → Crystallized → Equipped → Consumed (VE hide)

Категории: Focuses (оружие), Wards (броня), Glyphs (модификаторы), Relics (аксессуары), Scrolls (расходники), Keys/Seals (доступ), Structures (постройки)

Редкость: Common → Uncommon → Rare → Epic → Legendary

### 5.3 Крафт

```json
{
  "p": "VM", "v": 1, "t": "craft", "b": 12600000,
  "d": {
    "recipe": "emberblade",
    "materials": ["12500001", "12500032", "12500100"],
    "location": "loc:iron_forge:12200000"
  }
}
```

Качество = block_hash entropy + INT стат крафтера. Runescribe с высоким INT имеет реальное преимущество.

### 5.4 Зачарование (VE Протокол)

| VE Операция | Игровое Использование |
|---|---|
| append | Добавить зачарование (+5 POT fire rune) |
| edit | Перековка (iron sword → steel sword) |
| hide | Использование (выпить зелье) |

### 5.5 Торговля

**Доверительная:** Прямой transfer с репутацией
**Безопасная:** Через escrow с арбитром
**Аукцион запечатанных ставок:** Зашифрованные биды → раскрытие → победитель → эскроу

## ЧАСТЬ 6 — ГИЛЬДИИ

### 6.1 Членство = Делегирование SHARES

Элегантнейшая механика: делегируешь SHARES лидеру гильдии.
- Сохраняешь ownership, можешь отозвать в любой момент
- Effective SHARES лидера растут → усиление всей гильдии
- Отзыв делегирования = выход из гильдии
- Коррумпированный лидер → массовый отзыв → гильдия рушится органически

### 6.2 Казна через Beneficiaries

Члены устанавливают % десятины (tithe) на свои Award операции:
```json
{
  "beneficiaries": [
    {"account": "guild_vault", "weight": 1000}
  ]
}
```
10% эмиссии от каждого действия члена → в казну гильдии.

### 6.3 Гильдейские Войны

- Взаимный PvP даёт 2x XP
- Подсчёт побед
- Территории осаждаются
- Зашифрованные приказы для координированных атак

## ЧАСТЬ 7 — ТЕРРИТОРИИ

### 7.1 Территории как Аккаунты

Каждая территория — VIZ аккаунт (vm-ember-north и т.д.)

```
control_power(guild) = Σ(shares_delegated_to_territory_anchor by guild members)
```

Гильдия с наибольшим control_power контролирует территорию. Пересчёт ежедневно.

### 7.2 Осада (7 дней)

1. Объявление осады
2. 7 дней: обе гильдии копят siege power (Award территории + PvP победы)
3. Побеждает сторона с большим siege power
4. Проигравший — 28-дневный иммунитет

### 7.3 Создатель vs Контролёр

- Создатель Локуса: постоянная роялти 2-5%
- Контролирующая гильдия: налог 5-15% (настраиваемый)

## ЧАСТЬ 9 — ПРОГРЕССИЯ

### 9.1 Треки Прогрессии

| Трек | Источник | Измеряет |
|---|---|---|
| Level / Resonance | XP от всей активности | Общая сила |
| Class Mastery | Действия класса | Разблокировка умений |
| Renown | Социальная активность, лор | Социальный статус |
| Honor | Контракты, fair play | Доверие |
| Guild Standing | Вклад в гильдию | Ранг в гильдии |

Не только бой! Runescribe прогрессирует крафтом, Pactbinder — контрактами, авторы — лором.

### 9.2 Уровни

```
XP for level N = 1000 × N^1.5
```

| Уровень | Примерное время |
|---|---|
| 5 | 1 неделя |
| 10 | 3 недели |
| 20 | 2-3 месяца |
| 30 | 6 месяцев |
| 50 (soft cap) | 1+ год |

### 9.3 Пользовательские тексты как личные карты

**Магический постулат:**

> Текст должен Читаться и Видеться как карта. Так повелели Маги Вне Категорий...

Художественная ценность — обязательное входное условие. Её оценивают Денис и Лида, потому что живой пользовательский текст может быть совсем не похож на заранее придуманные примеры, но всё равно обладать художественной ценностью. Примеры и шесть требований помогают проверять пригодность текста для карты, но не заменяют человеческий художественный выбор.

Если текст принят к публикации, это означает, что он уже прошёл ключевое требование: по нему можно нарисовать карту. Поэтому опубликованный пользовательский текст **обязательно** получает нарисованную личную карту, и эта карта публикуется вместе с текстом. Публикация одного только текста без карты противоречит постулату.

#### Шесть требований к тексту

1. **Три масштаба чтения.** Из текста понятны весь путь, отдельные сцены и небольшие детали, которые можно обнаружить при рассматривании карты.
2. **Каждый персонаж действует.** Герои, жители и существа не перечислены декорацией: они идут, спорят, спасают, строят, ищут, прячутся, помогают или реагируют.
3. **Путь является частью мира.** Движение проходит через конкретные мосты, улицы, реки, леса, перевалы, суда или иные части описанного пространства.
4. **Есть намеренно крупный образ-якорь.** Один или несколько объектов могут быть сказочно увеличены ради ясности и чуда: дерево, зверь, башня, корабль, колокол, печь или иной оригинальный образ.
5. **Плотность чередуется.** Напряжённые и населённые эпизоды сменяются спокойными переходами; текст имеет ритм, а не состоит из одинаково громких событий.
6. **Сцены связаны причинно.** Следующее событие вырастает из предыдущего: погоня приводит к переправе, поломка — к ремонту, находка — к встрече, опасность — к спасению.

Если художественно ценный текст соответствует всем шести требованиям и принят к публикации, по нему создаётся личная оригинальная карта пользователя. Нельзя копировать охраняемых персонажей, готовые композиции и индивидуальную манеру живого художника.

#### Инструкция автору: как описать карту

Автору не обязательно заполнять анкету. Можно прислать цельный художественный текст. Но чтобы по тексту действительно можно было нарисовать карту, в нём должны читаться шесть опорных вещей:

1. **Начало и конец пути.** Где начинается путешествие и к чему оно приходит: площадь, мост, лесная опушка, гавань, башня, сад, мастерская, вершина или другое место.
2. **3–5 разных мест по дороге.** Через какие локации проходит маршрут: улицы, мосты, реки, леса, поля, болота, перевалы, лодки, лестницы, рынки, мастерские, острова.
3. **Жители и действия.** Кто встречается по пути и что делает каждый важный персонаж или существо: идёт, спорит, чинит, спасает, ищет, прячется, торгует, несёт, строит, пугается, радуется, помогает.
4. **Главное чудо или визуальный якорь.** Какой крупный запоминающийся образ должен быть на карте: огромное дерево, шагающий корабль, колокол размером с дом, небесная мельница, живая печь, гигантская добрая улитка или иной оригинальный объект.
5. **Ритм плотности.** Где происходит бурное событие, где спокойный переход, где новое открытие, где опасность, где передышка и где финал. Карта должна иметь дыхание, а не один непрерывный шум.
6. **Связь событий.** Почему герои переходят от одной сцены к другой: погоня ведёт к переправе, сломанный мост заставляет искать лодку, найденный ключ открывает башню, спасённое существо показывает дорогу.

Пример описания карты, понятный Лиде для рисования, до 700 знаков:

```text
У переправы из синих камышей лодочник чинит весло, а дети ловят светящихся рыб. Тропа уводит путников на рынок зеркальных чаш, где спорят торговцы и прячется маленький дракон. Когда мост ломается, все поднимаются по корням огромной яблони-маяка; в её кроне ветер крутит фонари. За тихой поляной с улиткой-стражем стоит башня: найденный ключ открывает в ней звёздную дверь.
Лида
```

Короткая форма для пользователя:

```text
Начало пути:

Места по дороге:

Кто там есть и что делает:

Главное чудо карты:

Где бурное событие, а где спокойная пауза:

Почему одно событие приводит к следующему:

Подпись автора:
```

Эта инструкция важна именно для модерации и рисования: если автор прислал не анкету, а художественный текст, Денис и Лида всё равно проверяют, можно ли из него извлечь эти шесть пунктов без переписывания авторского стиля.

#### Карточка опубликованного текста

- открывается как карта в полноэкранном доступном диалоге;
- полностью помещается без горизонтального и вертикального переполнения на экране `360×740` и больше при стандартном масштабе текста;
- основной текст: не более **700 знаков с пробелами** до утверждения финального стандарта;
- пользовательский размер шрифта не переносится в карточку: текст нормализуется к утверждённому игровому шрифту и кеглю, иначе пользователь может искусственно сломать макет слишком крупным шрифтом;
- временный минимальный стандарт шрифта: не меньше `16px`, межстрочный интервал не меньше `1.4`; финальный кегль утверждается отдельно;
- тонкое строгое магическое обрамление по краям;
- текст пользователя публикуется без стилистической переписи; допустима только отдельная проверка требований и безопасности;
- последняя текстовая строка — отображаемое имя автора;
- после имени визуально ставится печать; для скринридера сначала озвучивается имя, затем полное название печати и бонус;
- при увеличении системного шрифта допускается вертикальная прокрутка: доступность важнее декоративного требования «один экран».

На основном мобильном размере `390×844` экспериментальный макет вмещает до `1153` знаков, а компактный `360×740` — до `827`. Лимит `700` оставляет запас для абзацев, длинных слов и различий шрифтов. Имя и печать система добавляет отдельно и в 700 знаков не включает.

#### Печати и бонусы

Один опубликованный текст получает одну основную печать; бонусы печатей не складываются. Личная карта больше не считается бонусом печати: она обязательна для любой публикации принятого текста. А все остальные награды — тип печати, дополнительные `XP`, открытие платной карты или редкий переход/прыжок — выдаются на усмотрение Дениса и Лиды по художественной силе текста и месту события.

- **Печать Первого Оттиска** — текст соответствует шести требованиям и имеет художественную ценность. Дополнительный бонус: не обязателен.
- **Печать Живого Пути** — особенно сильные действия, характеры и читаемые эмоции. Возможный бонус: `+250 XP`.
- **Печать Связанной Судьбы** — особенно сильная причинная композиция и цельное путешествие. Возможный бонус: `+500 XP`.
- **Печать Магов Вне Категорий** — редкий высший выбор за выдающуюся художественную ценность. Возможный бонус: `+1000 XP`, одна случайная ещё закрытая карта Магической библиотеки навсегда или другой вручную выбранный редкий эффект.

#### Великий Магический Блок

**Великий Магический Блок** — лорное имя блокчейн-механизма, который неизменно фиксирует решение о публикации, печать и бонус.

Технически блок сам не способен оценить художественную ценность. Оценку делают Денис и Лида; после этого подтверждённое действие `story.seal` записывает хеш текста, аккаунт автора, отображаемую подпись, тип печати, выбранный бонус и ссылку на опубликованную личную карту. Хеш блока можно использовать как проверяемый источник случайности для выбора бонусной карты, но не как замену художественному отбору.

Для интриги публичная подпись может быть `неизвестный пользователь`, даже если внутренняя блокчейн-запись привязана к авторскому аккаунту. Условия приватности и раскрытия авторства задаются до отправки.

### 9.4 Фирменные игровые обозначения на картах

В будущих генерациях нельзя уходить к пустым или только разноцветным клеткам. Клетки — это не только техническая часть игры, но и часть игровой картины.

Для **Неизвестных карт Мира** и **Срединных карт Мира** нужно вернуть фирменный язык условных игровых обозначений:

- стрелки направления, поворотов и развилок;
- пиктограммы событий внутри отдельных клеток;
- простые игровые знаки опасности, тайника, встречи, перехода, отдыха, загадки, выбора, торговли, моста, портала или существа;
- редкие особые клетки, которые сразу выглядят как «здесь что-то произойдёт»;
- различимые символы без букв, цифр, логотипов и читаемого текста.

Обозначения должны быть декоративными и функциональными одновременно: помогать читать маршрут, усиливать атмосферу и сохранять ощущение настольной игры-ходилки. Пустые клетки допустимы только как редкая пауза для ритма, а не как основной стиль серии.

Для доступности в интерфейсе каждая опубликованная карта с такими знаками должна получать текстовое описание: какие типы клеток на ней есть и как устроен путь.

### 9.5 Правило мимики персонажей на картах

Соотношение персонажей держим ориентировочно **две трети с лицом и эмоцией / одна треть без лица, со спины, в маске, силуэтом или очень мелко**. Но важна не только пропорция, а качество мимики.

Видимое лицо должно читаться «выпукло»: ясная эмоция, выразительные брови, глаза, рот, наклон головы и жест. На мобильном масштабе зритель должен понимать, что персонаж удивлён, радуется, тревожится, спорит, зовёт, смущается, боится или заворожён. Нейтральные, смазанные, одинаковые кукольные лица и лица без отчётливого выражения не считаются выполненным требованием, даже если таких персонажей много.

Для генераций нужно прямо требовать: **crisp vivid expressive faces with high-contrast readable facial expressions at mobile scale**. Если эмоция видна только при сильном увеличении, карта проходит как красивая, но не проходит как эталон мимики.

Общий метод прорисовки эмоций для любых будущих генераций: эмоция задаётся не одним словом, а связкой видимых признаков. В prompt нужно указывать читаемые на мобильном масштабе брови, глаза, рот, наклон головы, положение плеч и рук, жест или движение тела, а также контраст света вокруг лица. На одной карте должны быть разные эмоциональные роли: кто-то заворожён, кто-то сомневается, кто-то улыбается, кто-то тревожится, зовёт или спорит. Персонажи без лица, в маске, силуэтом или со спины допустимы как ритмическая пауза, но они должны усиливать сцену, а не заменять всю работу с мимикой. Именно этот подход, использованный в серии «Карт Притяжения Мира», считается общим стандартом для следующих генераций.

### 9.6 Правило разнообразия генерации карт

Новый блок карт нельзя строить как повтор одного удачного шаблона с заменёнными декорациями. Каждая новая карта должна отличаться от уже принятых карт минимум по **четырём слоям** из этого списка:

1. **Главный образ-якорь.** Что первым запоминается на карте: существо, здание, природное чудо, механизм, город, мост, дерево, корабль или иной крупный мотив.
2. **Структура маршрута.** Форма пути: спираль, лестница, кольцо с возвращением, диагональ, островная цепь, два сходящихся пути, вертикальное восхождение, лабиринт без тупиков.
3. **Набор игровых символов в клетках.** Какие стрелки, развилки, события, опасности, встречи, тайники, загадки, порталы и особые клетки читаются внутри маршрута.
4. **Эмоциональный ритм.** Как чередуются напряжение, пауза, радость, тревога, открытие, выбор, смешное, странное, красивое и финальное чувство.
5. **Тип мира или биома.** Пустыня, риф, город, лес, болото, небо, подземелье, мастерская, рынок, зима, жара, сумерки, праздник, сон или иной слой мира.
6. **Характер жителей.** Кто населяет карту и чем занят: путники, мастера, звери, духи, торговцы, дети, стражи, музыканты, маски, механизмы, существа без лица.
7. **Причина движения.** Почему путь идёт дальше: поиск, спасение, спор, поломка, погоня, приглашение, долг, обмен, тайна, обещание, страх, притяжение или перемена.

Перед принятием новой серии нужно проверять не только красоту отдельных карт, но и отсутствие композиционных дублей внутри блока и относительно уже опубликованных карт.

### 9.7 Блок новой генерации: Срединные карты Мира

Рабочее название блока:

```text
Срединные карты Мира
переулок четвёртый
```

Описание блока:

> Ходят слухи что Мир делится на чёрный и белый, на добрый и злой, но это не так. Здесь намного больше и цветов и эмоций...

Идея блока — показать промежуточные состояния мира: не только победу или поражение, добро или зло, свет или тьму, а сомнение, перемену, смешанные чувства, выбор без очевидного правильного ответа, мягкие переходы между цветами, настроениями и сторонами пути.

### 9.8 Идея будущего блока: Страшные карты Мира

Пользователи, которым нравится пугаться, — отдельная важная аудитория. Если накопится достаточное количество подходящих рисунков и референсов, можно сделать отдельную серию из 15 карт под названием **«Страшные карты Мира»**.

Это не должно превращать Viz Magic в жестокий хоррор. Страх трактуется как игровая эмоция, сказочное напряжение, тайна, тревожное событие и встреча с существом, а не как натуралистичная жестокость.

Ситуация на страшной карте не должна быть безвыходной. Игрок проходит через УЖАС, но выход из карты должен ощущаться как спасение, облегчение и избавление, а не как переход в следующий кошмар. В первой генерации страшных карт безнадёжных карт быть не должно совсем. Возможность одной безнадёжной карты можно отдельно обдумывать только для второй серии карт страха; пока это не утверждённое решение.

Пять направлений для будущей серии:

1. **Страх как эмоция.** Карта строится вокруг выражений, поз, ожидания, неизвестности, тревожной тишины и реакции персонажей.
2. **Страх как событие.** Путь проходит через ночной переполох, погоню, исчезновение моста, оживший дом, внезапный туман или другое событие, которое меняет маршрут.
3. **Страх как конкретное существо.** На карте есть узнаваемый сказочный источник страха: тень, зверь, дух, кукла, огромная птица, сторожевой червь, маска или иное существо.
4. **Страх как сам себе.** Сам путь, карта, пустота, повторяющийся коридор, зеркало, неверная лестница или взгляд изнутри становятся источником страха.
5. **Страх как что-то необъяснимое.** На карте нет очевидного виновника: мир чуть-чуть неправильный, вещи стоят не там, тени не совпадают с предметами, дорога помнит шаги раньше путника, и игрок чувствует тревогу, которую невозможно сразу назвать.

Для доступности и возрастной мягкости такие карты должны оставаться читаемыми как приключенческие карты-ходилки: ясный маршрут, крупные клетки, отсутствие кровавого натурализма, без внезапных визуальных скримеров и без текста внутри изображения.

### 9.9 Идея будущего блока: Карты Притяжения Мира

Отдельная будущая серия может называться **«Карты Притяжения Мира»**. Она использует не сексуальный контент, а сильную эмоцию притяжения: красоту, харизму, магнетизм, сценическое обаяние, загадку, грацию, костюм, взгляд, танец, маски, праздник и желание рассматривать карту снова.

Эта серия не должна быть эротической или фетишистской. Она должна оставаться пригодной для общей аудитории: без обнажёнки, сексуальных поз, акцента на интимных частях тела, порно-стилистики и сексуализации несовершеннолетних. Сила серии — в эстетике, выразительности, романтическом напряжении без эротики и магической заворожённости.

Направления для будущей серии:

1. **Притяжение как эмоция.** Персонажи и сцены притягивают взгляд красотой, уверенностью, нежностью, тайной, смущением, гордостью или сценическим обаянием.
2. **Притяжение как событие.** Путь проходит через бал, маскарад, праздник фонарей, состязание, тайный танец, встречу у зеркала или ритуал, где герои выбирают, кому доверять.
3. **Притяжение как конкретное существо.** На карте есть завораживающий сказочный источник притяжения: фейри, сирена без эротизации, зеркальный дух, звёздный танцор, дракон красоты, живая маска или иное магическое существо.
4. **Притяжение как сам путь.** Сама карта слишком красива, чтобы ей сразу доверять: узоры, свет, музыка, отражения и дороги манят игрока вперёд.

Структура блока в Магической библиотеке:

1. **Ночная обсерватория масок и фонарей** — первая утверждённая карта блока. Карта-праздник с золотой рамкой, звёздной обсерваторией, мостами, садом статуй, зеркалами, шатрами и фонарным карнавалом. Путь идёт снизу от ярмарочных ворот через зеркальный сад и воздушные мосты к верхней обсерватории. Клетки возвращают фирменные игровые обозначения: ключи, маски, луна, звезда, кристалл, мост, фонарь, цветок, спираль, соединённые кольца и стрелочные треугольники.
2. Простая разделительная черта.
3. Под чертой название второго списка: **«Взросление»**.
4. Ниже остальные карты блока в художественно выбранной последовательности.

Файл первой карты: `app/assets/library-maps-attraction/attraction-map-01.jpg`.

Для остальных 14 карт нужно сохранять направление первой карты: безопасное притяжение, праздник, маски, красота, заворожённость и особенно отчётливая мимика персонажей. Эти карты формируют линию «Взросление»: от внешнего блеска и приглашения к выбору, доверию, смущению, внутренней смелости и более зрелому владению собственным магнетизмом.

### 9.10 Идея будущего блока: Не заселённые карты Мира

Давно желаемый будущий блок: **«Не заселённые карты Мира»**.

Это карты, где маршрут, клетки, порталы, мосты, башни и игровые символы уже существуют, но жителей почти нет или нет совсем. Такие карты не пустые: в них есть следы жизни, ожидание, готовые дороги, оставленные предметы, свет в окнах, запертые ворота, спящие механизмы и ощущение, что Мир ещё не решил, кого сюда пустить.

Легенда блока должна объяснить, **почему карты не заселены**. Рабочее направление легенды: эти места проявились раньше своих жителей. Мир сначала нарисовал дороги, правила, перекрёстки и порталы, а потом замолчал. Возможно, жители ещё идут сюда из других карт; возможно, их имена не записаны в Великий Магический Блок; возможно, карта ждёт первого игрока, который совершит поступок и тем самым заселит её.

Первая утверждённая карта блока:

1. **Перекрёсток парящих кристаллов** — квадратная фэнтези-карта над облаками: нижняя стартовая площадка со звездой, золотой путь через острова с башнями, деревьями и кристаллами, центральный перекрёсток, боковой остров с рунами и верхний штормовой портал в кристальной короне. Клетки крупные и читаемые, часть содержит простые символы. Карта хорошо подходит именно сюда: она выглядит как готовый небесный путь, где инфраструктура магии уже есть, а жители ещё не пришли.

Файл первой карты: `app/assets/library-maps-uninhabited/uninhabited-map-01.jpg`.

Ограничение: перед публикацией серии нужно удержать отличие от «пустых» карт. Не заселённость — это художественная идея, а не бедность изображения: должны оставаться маршрут, игровые обозначения, следы событий и причина, почему отсутствие жителей само становится тайной.

### 10.1 Обзор Системы

```
VIZ BLOCKCHAIN (источник истины)

  └── Детерминированные скрипты существ/квестов
```

### 10.2 Game State Engine

- Детерминированный (integer-only)
- Event-sourced (prev reference → порядок)
- Валидирующий (невалидные действия отбрасываются)
- Чекпоинтируемый (IndexedDB)

### 10.3 Протоколы

| ID | Назначение |
|---|---|
| VM | Viz Magic — все игровые действия |
| VE | VIZ Events — зачарование, потребление |

## ПОЧЕМУ ЭТО РАБОТАЕТ

### Три Столпа

1. **Блокчейн = Мир.** Нет отдельного сервера. Эфирный Леджер и есть игровой мир. Клиент — детерминированная линза.

2. **Award Routing создаёт глубину.** Разные заклинания направляют эмиссию разным получателям. Мана — реально дефицитный ресурс. Каждый каст — стратегический выбор.

3. **Volatile Loot решает проблему No-Seizure.** Первый Закон — фича, а не ограничение. Ставки: volatile лут + эскроу-ставки + территории + ранг.

### Эмерджентные Свойства

- Слова создают миры. Социальные посты становятся географией.
- Поддержка оплачивается. Beneficiary splits = хилеры, танки, крафтеры получают автоматическую компенсацию.
- Доверие заработано on-chain. Репутация вычисляется, а не декларируется.
- Гильдии органичны. Делегирование = обусловленная доверием власть.
- Прогрессивная децентрализация. Сначала разработчики запускают NPC, потом комьюнити.
